# LongCat-Image 算力与租用建议

## 直接结论

建议第一次租用：**同一台机器上的 2×昇腾 910B 64 GB，192–256 GB 主机内存，200 GB 可用 NVMe，租用 48–72 小时。**

这不是因为怀疑项目算力，而是为了把环境跑通、30 张基线测试、profiling 和一次适配优化放在同一个稳定实例内完成。单纯首图验证可以只租 24 小时，但中途换机器会增加驱动、镜像和缓存差异。

## 已确认数据、推测和安全余量

| 项目 | 数字 | 性质 | 对租用的影响 |
|---|---:|---|---|
| LongCat 模型文件 | 27.3 GiB | vLLM-Omni 官方资源表 | 模型盘不能只按“6B×2字节”估计；文本编码器、VAE等也需空间 |
| 1024×1024、batch=1 峰值 | 71.2 GiB | vLLM-Omni 官方 GPU 基线，未加速 | 不是 NPU 实测；作为第一版容量规划参考 |
| 官方 LongCat 示例 | BF16、50步、CFG 4 | 模型开发者数据 | 正式基线沿用，便于比较 |
| 单卡64GB是否一定能跑 | 不能确认 | 合理判断 | 71.2 GiB GPU基线已高于64GB，不把单卡64GB作为无优化保证方案 |
| 2×64GB能否直接把显存减半 | 不能保证 | 框架相关 | CFG parallel更偏速度；TP/Ulysses/VAE切片的内存收益必须真机记录 |

## NPU 配置建议

### 推荐档：2×64 GB

- 首次正确性：两卡只启用一种并行维度，建议先 `Ulysses=2`，不要同时叠加 CFG parallel、TP 和 Ring。
- 若 Ulysses 路径报错，再测试 `TP=2`。
- 首图开启 VAE slicing/tiling；跑通后关闭，得到未优化基线。
- 基线完成后再比较 CFG parallel=2 的延迟收益。

### 简化档：单卡 ≥80 GiB 可用 HBM

- 运维和日志最简单，适合先得到首图。
- 71.2 GiB 官方数字来自 GPU，单卡80 GiB仅有约8.8 GiB账面余量；NPU运行时、算子workspace和框架版本可能改变峰值。
- 若租用页面只写“80 GB”而没有说明可用 HBM，应向平台确认 `npu-smi info` 的实际容量。

### 冲刺档：4×64 GB

- 仅在计划同时做多种并行消融、Qwen-Image-2512对照或大量生成时值得。
- 对本课程项目，4卡会增加 HCCL 和并行参数调试成本，不是默认选择。

## 主机资源

- 内存：最低 128 GB；推荐 256 GB。CPU offload、模型加载和多进程会消耗额外内存。
- 磁盘：最低 120 GB 可用；推荐 200 GB NVMe。
  - LongCat：约 27.3 GiB；
  - vLLM-Ascend容器与安装缓存：保守预留 30–60 GiB；
  - 输出、日志、profiling：预留 20–40 GiB；
  - 仍需留临时下载和解压余量。
- CPU：最低 16 vCPU，推荐 32 vCPU。
- 网络：至少能稳定访问 `quay.io`、GitHub、Hugging Face或相应镜像；否则租用时间会浪费在下载上。

## 租用时长估算

| 工作 | 建议墙钟时间 |
|---|---:|
| 预检、容器拉取、源码安装 | 2–6小时 |
| 27.3 GiB模型下载与校验 | 0.5–3小时，取决于网络 |
| 首图和版本/算子排错 | 4–12小时 |
| 30张固定基准 | 用首张热启动延迟 `T` 计算，约 `30×T` 加模型启动时间 |
| profiler与一个优化点 | 8–16小时 |
| 优化后30张复测、整理答辩数据 | 4–8小时 |

推荐租用 48–72 小时；如果按卡时计费，2卡对应约 96–144 NPU-card-hours。实际价格取决于平台，计算式为：

```text
预计费用 = 单卡每小时价格 × NPU卡数 × 租用小时数 + 存储/公网流量费用
```

## 购买/租用前询问平台

1. 精确 NPU 型号与每卡实际 HBM。
2. 两卡是否同机，HCCS/HCCL拓扑是否可用。
3. 驱动是否兼容 CANN 9.1.0，是否已有 vLLM-Ascend 0.23.0 镜像。
4. 是否允许 Docker `--device` 映射和编译自定义算子。
5. 系统架构是 aarch64 还是 x86_64。
6. 系统盘、数据盘和容器盘分别剩余多少空间。
7. 出站网络、镜像源和带宽限制。
8. 关机后数据盘是否保留以及如何计费。
