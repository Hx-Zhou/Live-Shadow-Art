# 成员 B 后续执行手册

## 1. 第一次真人跑通（现在可做）

启动实验台 → 授权摄像头 → 单手入镜 → 张掌激活 → 平移 → 握拳暂停 → 捏合不应触发 → 再张掌 → 捏合攻击 → 丢手 → 回到画面后需重新张掌。

每一步记录是否通过。分别用左/右手试一次，检查镜像方向；快速移动不应直接换到旁人的手。模糊、弱光或过小的手可降低识别质量，优先调整距离与光照。

## 2. 正式采集

按计划书默认不保存原始画面，参与者使用 P01–P08 匿名编号，提前说明只导出坐标。导出的浏览器下载文件需手动归档。

建议 8 人：P01–P05 训练，P06 验证，P07–P08 独立测试。至少 3 人可验证脚本流程，但不等于达成计划书的采样规模。

| 项目 | 执行数量 |
|---|---|
| 5 类静态手势 | 每人每类约 60–80 有效帧，多个短片段、改变手型与姿态 |
| None / 过渡帧 | 每人约 200–240 帧，最终总量至少 35% |
| 总静态数据 | 约 4000–5000 帧，按导出数据实际统计 |
| 光照 | normal / dim / backlight 三种，每人各类别轮换覆盖 |
| 距离 | near / far 两种，记录实际约定（如 40 cm / 70 cm） |
| 左右手 | 每人每类均覆盖，避免只用单一手型 |
| 动态轨迹 | swipe / raise 每人每类 30–50 段，每段只做一次动作 |

静态采集：3 秒准备，10 秒采集，约 5 FPS；动态：3 秒准备，2 秒记录，最多约 30 FPS。无有效追踪手不保存坐标。动态片段由 `clipId` 分组，prepare 会跳过它们，保留原始 JSONL 供轨迹规则评测。

None 不等于“没有手”：请采集自然手型、放松、半握、整理袖口和手势转换。仅保存存在有效关键点的帧。纯无手时段用性能观察和丢手测试评估。

先人工抽查片段，删除准备/错误姿势混入的样本，再运行 prepare。禁止把一个人的相邻帧随机拆进测试集。测试参与者不可用于校准模型参数、调阈值或选模型；个人运行时校准可统一用于所有参与者并在报告说明。

## 3. 训练与报告

特征为手腕原点、掌宽/腕到中指根部尺度、左右镜像后的 63 维坐标 + 5 维角度 + 4 维指尖距离，共 72 维。训练与运行时共享 JS 特征代码，避免 Python 重写产生偏差。

NumPy MLP：72→128→64→6，ReLU，Adam，固定随机种子 42，按验证损失早停；约 1.8 万参数。标准化只拟合训练参与者。当前基线未启用 Dropout 或数据增强，可作为后续对照实验，不宣称已完成这些增强。

训练前检查每个 split 都有全部 6 类，None 总量 ≥35%，编号无重叠。训练输出包含混淆矩阵、各类 precision/recall/F1、6 类 Macro-F1、5 类核心手势 Macro-F1 和阈值。None 必须仍计入完整报告。

运行 check-model 验证真实测试帧的 Python / JS 概率一致。模型选择只看验证集；最终测试报告冻结后再做一次正式评测。若不达标，记录失败，不修改测试集来提高指标。

## 4. 动态事件评测

按 clipId 从原始 JSONL 逐段回放，记录人工动作开始时间、期望 action、首次命中时间、漏检、重复触发和错误类别。每段前 0.5 秒张掌激活或明确以激活状态开始，单次轨迹不应产生多次动作。自然无指令片段另用于误触评估。

可先运行 `node tools/evaluate-trajectories.mjs work/dynamic-report.json data/dynamic.jsonl`，按片段统计命中、重复及错误类别。脚本假定片段开始时控制已激活；丢手仍会进入安全状态。片段开始不等于动作开始，首次事件距片段开始的时间不是端到端延迟。

建议比较：规则 vs MLP；滤波关闭 vs 开启；正常光照 vs 弱光；近 vs 远；左 vs 右。当前没有自动标注动态动作起止的工具，需人工标注。事件级 precision/recall 不能由逐帧分类混淆矩阵替代。

## 5. 性能验收

| 指标 | 计划书目标 | 测量方法 / 当前状态 |
|---|---|---|
| 正式舞台渲染 | ≥30 FPS | 成员 C 完整场景录制、音效、两角色联调，当前占位 FPS 不能代替 |
| 核心静态 Macro-F1 | ≥0.95 | 独立参与者测试，保留 None 与全部类别报告；待数据 |
| 自然误触 | ≤1 次/分钟 | 至少 5 分钟/条件的无指令自然活动，观察员按钮计数；待真人 |
| 端到端 P95 | 数值待团队冻结 | 高帧率外部录像，同画面拍手和屏幕，多次动作统计差值；待真机 |
| 单次 MLP 分类 | <2 ms（计划目标） | 预热后测分类函数，单列中位数/P95，不能用整个 MediaPipe 耗时代替 |

页面 P95 是取帧提交→Worker→事件输出，包含队列、复制和滤波计算，**不含曝光、OS 相机缓冲、显示刷新、动作判定的稳定等待和成员 C 的渲染**。不能将其称为摄像头到角色响应延迟。

测试条件建议：正常/弱光/背光 × 近/远 × 左/右，遮挡 100 ms 和 300 ms、多人背景干扰、权限拒绝、摄像头断开、页面后台、启动失败与恢复。每个条件记录设备、浏览器、模型版本、校准参数、运行时长及失败次数。

## 6. 故障回退

- 权限拒绝：浏览器地址栏站点权限允许摄像头，关闭占用相机的程序。
- 模型加载失败：检查 vendor 文件，运行 setup；离线展示前完整预热一次。
- 推理慢：保持默认 640×480；缩小最终舞台特效，测试最终浏览器；保留键盘回退。
- 持续误触：先检查数据 None 比例和错误标签，再调验证集阈值；丢手后重置。
- 页面隐藏或设备断开：停止并重新启动，相机恢复后张掌激活。
- 8765 端口被占用：关闭旧的实验台服务窗口，或继续使用已经运行的同一版本。
